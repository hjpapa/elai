## 절대 하지 않는 것
- **`main` 체크아웃·커밋·머지·push, 브랜치 바꾸기, 배포를 하지 않아요.** 운영 사이트는 지금 발표에 쓰고 있어요. 끝나면 Claude가 검토한 뒤 합쳐요.
- `codex exec`처럼 다른 Codex를 띄우지 않아요.
- `supabase/**`, `src/services/**`, `src/teacher/**`, `src/missions/core/types.ts`, `docs/asset-spec.md`, `package.json`·잠금 파일, `vercel.json`, `vite.config.ts`, `index.html`, `teacher.html`, `assets-src/palette.json`은 고치지 않아요.
- 새 라이브러리를 넣지 않아요. 브라우저 자동화 도구나 그 결과물을 저장소에 넣지 않아요.
- `src/data/schema.ts`, `src/game/assets.ts`는 **자기 지시서의 "미리 승인한 계약 변경"에 적힌 곳만** 고쳐요.

## 다른 창과 겹치지 않게
- 자기 지시서의 "고쳐도 되는 파일"만 고쳐요. 꼭 필요한 다른 변경은 고치지 말고 최종 보고의 **필요한 변경**에 적어요.
- 스타일은 `src/ui/styles.css`에 넣지 않고 **자기 모듈 옆의 새 CSS 파일**을 만들어 그 모듈에서 `import`해요(예: `src/ui/shop.css`).
- `src/game/rpg/state.ts`, `src/data/maps/village.ts`, `src/game/scenes/WorldScene.ts`는 두 창이 함께 고칠 수 있어요. 지시서가 정한 자리에만 더하고, 파일을 다시 정렬하거나 서식을 바꾸지 않아요.
- `npm run assets`와 `public/assets/**` 변경은 **C24만** 해요.
- `docs/curriculum.md`는 C22만, `docs/tasks/README.md`와 `CLAUDE.md`, `AGENTS.md`는 아무도 고치지 않아요(Claude가 합칠 때 고쳐요).

## 지금 학생 기록을 지켜요
- 이미 진행 중인 저장(`elai-save-v1`, 학급 저장)을 그대로 불러올 수 있어야 해요. 예전 저장에 새 필드가 없어도 동작해요.
- **기존 미션·파트·맵·아이템·몹·놀이 판의 id를 바꾸지 않아요.**
- **필수 미션을 새로 넣지 않아요.** 새 미션은 C22의 선택 미션 규칙만 써요.
- 기존 미션의 경험치와 레벨 성장 곡선을 바꾸지 않아요. 몹의 체력·공격력·경험치·보상도 그대로예요.
- 시연 모드(`/?demo`)는 지금처럼 동작하고, 일반 저장을 읽거나 바꾸지 않아요.

## 학습 설계 규칙
- 미니게임과 미션 결과는 학생의 선택과 프로그램으로만 정해져요. 뽑기·운·코인 걸기는 만들지 않아요.
- 레벨과 장비가 문제 풀이를 대신하면 안 돼요. 학습 우회 방지 테스트를 약하게 만들지 않아요.

## 학생에게 보이는 글
- 해요체예요. 말풍선은 한 번에 2줄 이내, 한 줄 약 20자예요.
- 0~3장은 쉬운 낱말을 쓰고, 어려운 말은 뜻을 함께 적어요.
- 실존 인물·브랜드·기존 게임의 이름과 캐릭터를 쓰지 않아요.
- 성별·외모·직업 고정관념이 없는 예시와 다양한 이름을 써요.
- 몹은 고장 난·장난꾸러기 존재이고, 이기면 수리·정화돼요. "죽이다, 처치, 피" 같은 말은 쓰지 않아요.
- 이름·주소·전화번호·학교·얼굴 사진을 묻거나 입력하게 하지 않아요.
- 사실 내용은 초등학생에게 쉽게 말하되 틀리지 않게 써요. 확실하지 않은 사실은 쓰지 않아요.

## 코드와 테스트
- TypeScript strict를 지키고 `any`를 쓰지 않아요. 화면 글은 한국어, 식별자는 영어예요.
- 기존 테스트를 지우거나 약하게 바꾸지 않아요. **자기 지시서의 "미리 승인한 테스트 변경"만** 고칠 수 있어요.
- 새 규칙은 테스트를 함께 더해요. 화면 없이 검사할 수 있는 규칙은 순수 함수로 나눠요.
- 끝낸 단계마다 `npm test && npm run build`가 통과해야 해요.

## 개발 서버와 브라우저 확인
- 자기 포트만 써요: `npm run dev -- --port <포트> --strictPort`. **5173은 쓰지 않아요**(사용자의 저장 기록이 있어요). 다 쓰면 꺼 주세요.
- 작업 폴더에는 `.env`가 없어서 제목 화면이 바로 "이 기기에서 체험"이에요.
- 개발 서버에서는 `window.__app`을 쓸 수 있어요. `/?demo`의 시연 메뉴로 장·건물·미션에 바로 갈 수 있어요.
- 새 화면은 1366×768, 390×844, 320×640에서 가로 넘침과 잘린 글이 없는지 확인해요.

## 단계마다 할 일
1. 그 단계를 끝내고 `npm test && npm run build`를 통과시켜요.
2. 브라우저에서 실제로 눌러 확인해요.
3. `docs/tasks/codex-<번호>-progress.md`에 한 일, 확인 결과, 남은 문제를 적어요.
4. 사용자가 단계마다 커밋하라고 했으면 자기 브랜치에 커밋 하나를 해요. 메시지는 `C<번호>-<단계>: <이름>`이에요.

중간에 멈췄다가 다시 시작하면 진행 기록과 `git log`를 먼저 보고 끝나지 않은 단계부터 이어서 해요. 시간이 모자라면 앞 단계부터 끝내고, 뒤 단계는 남겨 두고 보고해요.
