# Codex 로드맵 — 2~8장 (Claude 할당량 절약 기간)

Claude 할당량을 아끼는 동안 남은 장을 Codex가 단계별로 만들어요. Claude는 할당량이 다시 차면 단계별 커밋을 검토하고, 게임 엔진 구조를 이어서 다듬어요.

- **C4(2장)**는 자세한 지시서 [codex-04-ch2.md](codex-04-ch2.md)가 있어요. 먼저 그것부터 해요.
- **C5~C10**은 이 문서의 단계 요약만 있어요. 단계를 시작할 때 Codex가 C4와 같은 형식으로 자세한 지시서를 먼저 써요.

## 진행 규칙
1. **한 번에 한 단계**만 해요. 순서는 C4 → C5 → C6 → C7 → C8 → C9 → C10이에요. 앞 단계가 끝나고 커밋된 뒤에 다음 단계를 시작해요.
2. 단계를 시작하면 먼저 `docs/tasks/codex-NN-chN.md` 지시서를 써요. 항목은 C4와 같아요(목표, 먼저 읽을 것, 고쳐도 되는 파일, 미리 승인한 계약 변경, 엔진, 데이터, 그림, 테스트, 문서, 완료 기준, 최종 보고). 그다음 그 지시서대로 구현해요.
3. 고쳐도 되는 파일과 고치지 않는 파일은 C4와 같아요. 계약 변경은 아래 "모든 단계에 미리 승인한 계약 변경"과 단계마다 적힌 것만 해요. 그 밖의 계약 변경이 꼭 필요하면 그 부분은 만들지 말고 최종 보고의 "필요한 변경"에 적어요.
4. 끝내기 전에 `npm run assets && npm test && npm run build`가 통과하고, `npm run dev`에서 그 장을 처음부터 끝까지 직접 해 봐요. 0·1장, 7장 미리 해 보기, 앞서 만든 장도 그대로 동작해야 해요.
5. **커밋은 사용자가 요청할 때만** 해요. 지금 작업 브랜치(`codex/04-chapters`)에 단계마다 커밋 하나를 만들고, 첫 줄은 `C5: 3장 갈림길 사막`처럼 써요. main 브랜치, push, 머지, 브랜치 바꾸기는 하지 않아요. 사용자가 [codex-run-all.md](codex-run-all.md)로 한 번에 맡기면, 그 부탁이 단계마다 커밋하라는 요청이에요.
6. 단계 지시서에서 아래 제안과 다르게 만들고 싶으면, 다르게 만드는 까닭을 지시서에 적어요. 다만 "배우는 개념 = 게임 능력" 원칙과 학습 우회 방지 테스트는 꼭 지켜요.

## 모든 단계에 공통
### 장 하나에 들어가는 것(1·2장이 본보기)
- 맵 2개: 입구 맵(NPC, 몹 2마리, 상자, 소품, 표지판, 마을 포털) + 던전(안개, 그 장의 개념을 연습하는 구조, 보스 방)
- 장 NPC 1명(파트 1~3 미션), 몹 1종, 보스 1종(전투와 퀴즈), 로비 부품 1개, 로비에게 설명하기(reflect)
- 보스 보상: 배지 `badge-N`, 칭호, 장비 1개, 플래그 `village-restore-N`·`chN-clear`
- 마을: `to-chN` 포털(`open: { flag: 'ch(N-1)-clear' }`), 복구 N단계 장식
- 장 데이터: `status: 'playable'`, `entryMap`. 지금 들어 있는 장의 학습 목표·성취기준·파트 id·제목은 유지하고, 임시 미션(`note`만 있는 것)을 실제 미션으로 바꿔요.

### 설계 원칙
- **배우는 개념 = 게임 능력.** 새 개념은 로비 부품이 여는 새 카드·능력이에요. 레벨과 장비는 돕기만 하고 문제 풀이를 대신하지 못해요.
- 퍼즐과 전투는 같은 인터프리터(`run(program, env)`)를 써요. 블록의 뜻이 어디서나 같아요.
- **학습 우회 방지 테스트**(장마다): 의도한 풀이는 권장 레벨에서 다치지 않거나 거의 다치지 않고 이겨요. "공격만 반복" 같은 단순한 프로그램, 그 장의 개념을 쓰지 않은 프로그램은 져요.
- **성장 곡선 테스트**: 본편(미션·몹·상자)만으로 그 장 보스의 권장 레벨에 닿아요. 레벨·능력치·슬롯 공식은 바꾸지 않고, 몹 수치와 보상 경험치로 맞춰요. 새 로비 부품은 슬롯을 늘리지 않고 카드·능력만 열어요.
- 권장 레벨 제안: 3장 보스 8, 4장 10, 5장 11, 6장 12, 7장 13, 8장 14
- 비폭력: 몹은 고장 난·장난꾸러기 존재이고 이기면 정화되어 친구가 돼요. 실패해도 잃는 것 없이 다시 해요. 순위표·확률 뽑기는 없어요.
- 2번 실패하면 힌트, 3번이면 첫 칸을 알려 주는 기존 도움 흐름을 새 미션 엔진에도 붙여요.

### 새 미션 엔진
- `src/missions/core/types.ts`의 `MissionEngine` 인터페이스를 **그대로** 구현해요(인터페이스는 바꾸지 않아요). 기존 엔진(`blockCode`, `quiz`, `prompt` 등)을 본보기로 삼아요.
- 결과(별·시도·힌트)는 지금처럼 `MissionResult`로 돌려줘서 교사 표에 자동으로 나오게 해요.

- 휴대폰(375px) 화면과 터치로 쓸 수 있어야 해요. 끌어 놓기에는 누르기 대신 쓰는 방법도 함께 둬요.

## 단계

### C5 — 3장 갈림길 사막(4~5학년): 조건, 센서, 규칙 추론
- 배울 것: "만약 ~라면"(조건), 센서(로봇이 주변을 알아내는 입력 장치), 질문 규칙으로 나누기(결정 트리 맛보기)
- 로비 부품 `sensor` 센서 → 전투 **만약 카드**(`if` 블록, 조건은 `enemySmash` 같은 기존 `Cond`)
- 몹 **신기루 도마뱀**: 예고의 일부가 "?"로 가려져요. 가려진 차례는 라운드마다 두 행동 중 하나로 바뀌어요(씨앗이 있는 난수라 테스트할 수 있어요). 조건은 그 차례의 진짜 행동을 봐요. → 평평한 프로그램은 어떤 씨앗에서는 꼭 지고, `만약 강타 준비면 막기, 아니면 공격` 같은 조건 프로그램은 여러 씨앗에서 모두 이겨요(테스트).
- 미션
  - p1 신호등 규칙: 조건 블록 퍼즐. 칸의 신호에 따라 멈추거나 가요(필요하면 `Cond`에 신호 조건 더하기).
  - p2 센서 로봇: `wallAhead`·`pathLeft`·`pathRight`와 `forward`·`turnLeft`·`turnRight`로 장애물 피하기. 같은 프로그램이 모양이 다른 길 두세 개에서 모두 통해야 성공(조건의 힘).
  - p3 스무고개 AI: `classify` 엔진 "질문 나무" 모드. 질문 카드("날개가 있나요?")를 골라 나무를 만들면 동물·물건 카드가 그 나무를 따라 나뉘어요. 모든 잎이 한 종류만 남으면 성공.
  - 보스 m1 모래 폭풍 미로: 안개 미로를 "오른손 규칙" 프로그램으로 자동 탈출(`반복 { 만약 오른쪽이 열렸으면 오른쪽으로 돌고 앞으로, 아니면 … }`). 지금 있는 블록으로 돼요.
  - 보스 m2 전투(도마뱀 대장), 퀴즈, 로비에게 설명하기
- 지금 `ch3.ts`의 미션 종류·메모를 기준으로 하되, 위처럼 다듬어도 돼요.

### C6 — 4장 데이터 항구(5학년): 아날로그·디지털, 데이터 종류, 수집·정리·시각화, 0과 1
- 로비 부품 `dataLens` 데이터 렌즈 → 전투 **살펴보기 카드**(`BattleCmd`에 `scan`, 에너지 0): 그 라운드에 몹이 한 행동을 도감 표에 기록해요.
- 몹 **안개 해파리**: 행동이 눈에 보이는 값(예: 물결 높이 1~3)에 따라 달라져요. 살펴보기로 모은 기록을 도감 표에서 보면 규칙을 찾을 수 있고, 그 규칙을 조건 카드로 써서 이겨요(데이터를 모아 정리하면 규칙이 보인다). 필요하면 `Cond`에 그 값을 묻는 조건을 더해요.
- 미션
  - p1 데이터 모으기·나누기: `classify` "나누기" 모드(아날로그/디지털, 숫자·글·그림·소리 데이터)
  - p2 표·그래프: 모은 자료로 표를 채우고 막대그래프를 만들어 질문에 답해요(퀴즈 엔진에 표·그래프 보기를 더하거나 작은 새 화면)
  - p3 이진수 등대: 등불 켜기/끄기(1/0)로 수를 만들어 문을 열어요. 던전 문도 이진수 신호로 열려요.
  - 보스 m1 엉망 장부 정리(전처리): 빠진 값·잘못 적은 값·겹친 기록을 찾아 고쳐요(`classify` 나누기 또는 새 모드)
  - 보스 m2 전투, 퀴즈, 설명하기

### C7 — 5장 인식의 연구소(5~6학년): 컴퓨터의 인식, 특징, 분류, 지도학습, 군집 맛보기
- 로비 부품 `learnChip` 학습 칩 → 전투 **분류 능력**: 학생이 학습시킨 모델을 전투에서 써요.
- `train` 엔진(새로): 예시에 이름표를 붙이고(라벨링) → 학습(가장 가까운 예시 찾기, k-최근접 이웃처럼) → 새 예시로 시험해서 맞힌 비율을 보여 줘요. 예시가 적거나 한쪽으로 치우치면 틀리는 것을 직접 보게 해요. 평가는 순수 함수로 테스트해요.
- 미션
  - p1 컴퓨터의 눈: 그림이 숫자 격자(픽셀)라는 것, 특징(예: 귀가 뾰족함, 칠한 칸 수) 찾기
  - p2 이름표 붙이기 vs 비슷한 것끼리 묶기: `classify` "나누기"와 "묶기"(이름표 없이 비슷한 것끼리, 군집 맛보기) 모드
  - p3 나만의 분류 AI: `train`으로 라벨링 → 학습 → 시험
  - 보스: 변신 슬라임 대장이 친구 몹과 장난꾸러기 몹 모습을 섞어 보여요. 학습시킨 분류로 차례마다 맞는 카드를 골라요. 학습 데이터가 좋을수록 쉬워져요. 퀴즈, 설명하기.

### C8 — 6장 길잡이 천문대(6학년): 탐색과 예측, 정확도
- 로비 부품 `predictor` 예측 모듈 → 전투에서 **다음 행동 예측 표시**: 이 전투에서 지금까지 본 기록으로 다음 행동을 확률처럼 보여 줘요. 기록이 쌓일수록 잘 맞아요(틀릴 수도 있다는 것도 보여요).
- 몹 **별똥 여우**: 패턴이 길고 조금씩 바뀌어서, 예측 표시를 보고 프로그램을 고치면 이겨요.
- 미션
  - p1 물결 탐색: 출발점에서 1칸, 2칸, … 물결처럼 퍼져 가장 짧은 길을 찾아요(너비 우선 탐색을 눈으로 보기). 던전의 가장 짧은 길 찾기와 이어져요.
  - p2 날씨 예측: `train` 엔진 예측 모드(구름·바람·습도 → 맑음/비)
  - p3 데이터가 적으면? 많으면?: 같은 문제를 예시 수만 바꿔 학습해서 정확도를 비교해요
  - 보스 별자리 미궁 + 전투, 설명하기

### C9 — 7장 프롬프트 공방(5~6학년): 생성형 AI 원리, 좋은 프롬프트, 고쳐 묻기, 사실 확인
- 지금의 "미리 해 보기"(글 주문서 `ch7-p2-m1`, 젠)는 그대로 살리고 장 전체로 넓혀요.
- 로비 부품 `talkModule` 대화 모듈
- 미션
  - p1 다음 말 맞히기: `nextWord` 엔진. 작은 글 모음에서 다음에 올 말의 횟수를 막대로 보여 주고, 골라 가며 문장을 만들어요. 글 모음을 바꾸면 결과도 바뀌어요("그럴듯해도 틀릴 수 있어요").
  - p2 글 주문서: 지금 미션 + 고쳐 묻기 미션 하나 더
  - p3 그림 주문서: `prompt` 엔진 그림 모드. 주인공·배경·시간·스타일 픽셀 레이어를 합쳐요(`PromptData`에 선택 필드 더하기). 고쳐 묻기는 감점하지 않아요.
  - 보스 엉터리 AI(헛소리 앵무새): `factCheck` 엔진. AI가 쓴 글에서 틀린 문장을 찾고, 게임 속 "믿을 만한 자료" 카드로 확인해 고쳐요. 퀴즈.
- 안전 문구를 꼭 넣어요: 이름·주소·전화번호·학교·얼굴 사진은 넣지 않아요, AI 도움을 받았으면 밝혀요. 실제 AI 서비스에 연결하지 않아요.

### C10 — 8장 윤리의 성(6학년): 편향, 개인정보, 딥페이크, 정직한 AI 사용, 사람이 최종 결정 + 엔딩
- 로비 부품 `ethicsCore` 윤리 코어 → 최종 각성
- 미션
  - p1 치우친 데이터 찾기: `classify`로 데이터 묶음에서 빠지거나 너무 많은 것을 찾아 고르게 고쳐요
  - p2 개인정보 지키기: 올려도 되는 것/안 되는 것 나누기
  - p3 진짜? 가짜?: `factCheck` 그림·글 모드. AI가 만든 것에 표시를 붙이고, 확인하는 방법을 골라요
  - 보스 편향 골렘: 학생이 앞 미션에서 데이터를 고르게 고친 만큼 골렘이 약해져요(플래그나 저장 기록으로 연결). 설명하기.
- **엔딩**: 배지 8개를 모으면 마을에서 "생각하는 AI"를 깨우는 장면(대화, 로비 완성 모습, 배지·칭호 돌아보기). 교육부 AI 윤리원칙의 대원칙 "사람의 성장을 지원하는 AI"를 쉬운 말로 담아요.
- 교사용 문서(`docs/curriculum.md`)의 8장·마무리 차시를 실제 미션에 맞춰 고쳐요.
