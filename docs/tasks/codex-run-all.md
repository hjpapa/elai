# Codex 연속 실행 — C4부터 C10까지 한 번에

사용자가 이 문서대로 하라고 하면, 2장(C4)부터 8장·엔딩(C10)까지 **사람의 확인 없이 차례로** 끝까지 해요. 중간에 멈췄다가 같은 부탁을 다시 받으면, 끝낸 단계는 건너뛰고 이어서 해요.

이 부탁이 곧 사용자의 **"단계마다 커밋해 줘"** 요청이에요(`AGENTS.md`의 할당량 절약 기간 규칙).

## 0. 시작할 때마다 확인
1. 작업 폴더가 `C:\code\elai-wt\codex-04`이고 브랜치가 `codex/04-chapters`인지 봐요. 아니면 아무것도 고치지 말고 멈춰서 알려요.
2. `git log --oneline`과 `docs/tasks/codex-progress.md`로 끝낸 단계를 확인해요. 커밋 첫 줄이 `C4:` ~ `C10:`인 단계는 끝난 거예요.
3. `git status`에 커밋하지 않은 변경이 있으면, 끝내지 못한 단계의 작업이에요. 그 단계의 지시서를 다시 읽고 이어서 해요(처음부터 다시 만들지 않아요).

## 2. 단계마다 하는 일
1. **지시서**: C4는 있는 지시서를 따라요. C5부터는 `docs/tasks/codex-roadmap.md`의 그 단계 요약을 보고 `docs/tasks/codex-NN-chN.md`를 C4 지시서와 같은 항목으로 먼저 써요. 앞 단계에서 실제로 만든 코드(엔진·데이터 형식)에 맞춰 써요.
2. **구현**: 지시서대로 만들어요. 규칙은 `AGENTS.md`, 원칙·계약 변경 범위는 로드맵을 따라요.
3. **확인**: `npm run assets && npm test && npm run build`가 모두 통과해야 해요. 그 장의 학습 우회 방지·성장 곡선 테스트가 있어야 하고, 앞 장 테스트도 모두 통과해야 해요. `npm run dev`로 화면을 직접 확인할 수 있으면 하고, 못 하면 보고에 "확인 못 함"으로 적어요.
4. **기록**: `docs/tasks/codex-progress.md`에 그 단계의 최종 보고(지시서의 "최종 보고" 항목)를 더해요. 단계마다 `## C5 — 3장 갈림길 사막`처럼 제목을 달아요.
5. **커밋**: `git add -A` 뒤 위 표의 첫 줄로 커밋해요. 둘째 줄부터 바꾼 내용을 몇 줄로 요약해요.
6. 바로 다음 단계로 넘어가요. 중간에 사용자에게 묻지 않아요.

## 3. 멈추는 경우
- 테스트·빌드를 고치려고 충분히 애써도 통과하지 않으면 **커밋하지 말고** 멈춰요. 무엇이 왜 안 되는지 `codex-progress.md`와 마지막 메시지에 적어요. 다음 단계로 넘어가지 않아요(뒤 단계가 앞 단계 위에 쌓이니까요).
- 승인 범위 밖의 계약 변경이 필요하면 그 부분은 만들지 말고 "필요한 변경"에 적어요. 그 장을 처음부터 끝까지 플레이할 수 있으면 계속 가고, 플레이할 수 없으면 멈춰요.
- 하지 않는 일: push, main 브랜치 건드리기, 머지, 브랜치 바꾸기, 이미 만든 커밋 고치기(amend·rebase·reset), 새 라이브러리 설치.
