## 1단계: 시연 모드

### 켜는 법
- 주소에 `?demo`가 있을 때만 켜져요(`/?demo`). 화면 어디에도 이 주소로 가는 링크를 두지 않아요.
- `src/game/rpg/demo.ts`에 `isDemoSearch(search: string): boolean`을 두고, `src/main.ts`에서 `app.demo`를 정해요(`src/game/app.ts`에 `demo: boolean` 추가).

### 제목 화면
- 시연 모드면 학급/체험 탭 대신 **시연 모드 상자**를 보여 줘요. 학급 입장과 서버 연결 코드는 지나가지 않아요.
  - **시연 시작**: 시연 저장이 있으면 이어서, 없으면 0장 상태로 시작해요.
  - **처음 상태로 시작**: 시연 저장을 0장 상태로 새로 만들어요.
- 저장은 `setSaveProfile('demo')`를 써서 `elai-save-v1:demo`에만 남겨요. 일반 저장 `elai-save-v1`과 학급 학생 저장은 읽지도 바꾸지도 않아요.
- `app.classLink`는 `null`이고 서버로 아무것도 보내지 않아요.

### 시연 상태 만들기(`src/game/rpg/demo.ts`, 화면 없는 순수 코드)
`buildDemoSave(stop: number, settings?: SaveData['settings']): SaveData`
- `stop` 0~8: 그 장을 막 시작하는 상태, 9: 엔딩 바로 앞 상태예요.
- 만드는 순서
  1. `freshSave('시연')`으로 시작해요(설정을 받으면 유지해요).
  2. `stop`보다 앞선 장의 모든 미션을 `completeMission(id, { success: true, stars: 3, attempts: 1, hints: 0 })`로 끝내요. 보상·플래그·배지·로비 부품·칭호가 평소 경로로 들어와요.
  3. `applySkipKit`으로 그 장을 시작할 때의 경험치·장비를 채워요(`stop` 9는 8장 기준).
  4. 5장을 지난 상태면 `ch5-p3-m1`의 예시(`examples`)로 분류 모델을 채워요(`setClassificationModel`, `k`는 미션 값). 5장 보스를 바로 열어도 전투가 돼요.
  5. 체력을 채우고 위치를 정해요: 그 장의 `entryMap`과 맵의 `spawn`, `stop` 9는 마을 `spawn`이에요.
- 사전 확인 결과(직접 돌려 봤어요): 이 순서로 0~8장 모두 다음 목표가 그 장 첫 미션이고, 마을 문이 열려요. 9는 엔딩 조건이 맞아요.

## 2단계: 전 화면 점검과 고치기
시연 모드와 개발 서버의 `__app`을 써서 자동으로 돌려요. 결과는 진행 기록에 표로 남겨요.

**화면 크기**: 1366×768, 1024×768, 768×1024, 390×844, 320×640

**대상**
- 미션 74개 전부(화면을 열고 첫 화면 확인 후 닫기). 대화 미션은 대화창, 전투 미션은 전투 화면이에요.
- 놀이 6개: 판 고르기 + 판마다 첫 화면(모두 36판)
- 가방, 도감 모든 탭, 메뉴, 시연 메뉴, 보상 창, 엔딩 창
- 맵 전부(`MAPS`): 들어갔을 때 오류가 없고, 플레이어와 HUD가 보여요

**문제로 치는 것**
- 콘솔 오류, 잡히지 않은 예외, 그림을 못 불러옴
- 문서나 창의 가로 넘침, 창 밖으로 나간 요소
- 실행·제출·닫기·다음 같은 주요 단추에 스크롤로도 닿을 수 없거나 다른 것에 가려짐
- 글자 잘림, 터치 조이스틱·HUD가 주요 단추를 가림
- 주요 단추의 터치 영역이 40×40px보다 작음

**실제로 걸어 보기**: 장마다 시연 메뉴로 이동 → '길 안내' → 목표 NPC까지 걸어가기 → 첫 미션 시작. 건물 하나는 문을 눌러 들어가고 문 매트로 나와요.

**고치는 방법**: 되도록 CSS로 고치고, 필요하면 화면 코드를 고쳐요. 규칙을 바꿔야 고칠 수 있는 문제는 고치지 말고 재현 방법과 함께 "필요한 변경"에 적어요. 논리 버그를 고쳤다면 그 버그를 잡는 테스트를 더해요.

## 3단계: 본편과 마을 건물 잇기
1. **새 놀이 알림**: 미션을 **처음** 끝내서 닫혀 있던 놀이 판이 열리면, 결과 창을 닫은 뒤 알려 줘요.
   - 예: `새 놀이가 열렸어요\n마을 과일 가게 3판`. 한 건물의 여러 판은 `5·6판`, 여러 건물이면 건물마다 한 줄이에요.
   - 미션 전후의 열림 상태를 비교하는 순수 함수를 `catalog.ts`에 두고 테스트해요. 시연 모드에서는 알리지 않아요.
2. **도감 '마을 놀이' 탭**: 놀이마다 아이콘, 놀이 이름, 건물, 받은 별(예: `12 / 18`), 판별 별, 받은 칭호를 보여 줘요. 안 해 본 놀이는 "아직 해 보지 않았어요."예요.
3. 테스트: 판의 열림 미션을 끝내면 그 판이 알림 목록에 나오고, 로비 부품으로 이미 열린 판은 나오지 않아요. 다시 해도 또 나오지 않아요.

경험치·동전·장 진도·교사 진도표에는 영향이 없어야 해요.

## 5단계: 시연 안내서(`docs/demo-guide.md`)
발표자가 화면을 보며 그대로 따라 할 수 있게 한 장으로 써요. 실제 화면에서 확인한 대로 적어요.
- 시연 주소(`https://elai-indol.vercel.app/?demo`)와 시작 전 준비(화면 크기, 소리)
- **10분 순서**: 마을과 조작 → 1장 블록 코딩 → 프로그램 전투 → 5장 분류 AI → 7장 프롬프트 → 8장 치우친 데이터 → 마을 건물 놀이(과일 AI 가르치기) → 엔딩. 단계마다 누를 곳과 한두 문장 설명
- 시간이 5분뿐일 때 줄이는 법
- 막혔을 때: 새로고침, '처음 상태로', 다른 장으로 넘어가기
- 교사 페이지는 실제 학급 계정이 필요해서 시연 전에 사람이 준비한다고 적어요. 비밀번호·학급 코드·개인정보는 문서에 넣지 않아요.

## 단계마다 할 일
1. 그 단계를 만들고 `npm test && npm run build`를 통과시켜요.
2. 브라우저에서 확인해요.
3. `docs/tasks/codex-21-progress.md`에 한 일, 확인 결과, 남은 문제를 적어요.
4. 사용자가 단계마다 커밋하라고 했으면 작업 브랜치 `codex/21-demo-ready`에 커밋 하나를 해요.
   - 메시지는 `C21-<단계>: <이름>`이에요(예: `C21-1: 시연 모드`).
   - main·push·머지·브랜치 바꾸기는 하지 않아요.

중간에 멈췄다가 다시 시작하면 진행 기록을 먼저 읽고 끝나지 않은 단계부터 이어서 해요.

## 완료 기준
- 끝낸 단계의 요구 사항과 테스트를 모두 채웠어요.
- `npm test`와 `npm run build`가 통과해요.
- 시연 모드가 아닐 때 동작이 바뀌지 않았어요.
- 허락된 파일만 바꿨어요.

## 확인 명령
```bash
npm test && npm run build
```
