# Codex 작업 C1 — 픽셀아트 그림 전체

## 목표
`src/game/assets.ts`에 있는 **모든 그림 키**를 픽셀아트로 만들고, 텍스트 원본에서 PNG를 만드는 생성 스크립트를 완성해요. 지금 게임은 단색 임시 그림으로 돌아가는데, 이 작업이 끝나면 진짜 그림으로 바뀌어요.

## 먼저 읽을 것
1. `AGENTS.md` — 공동 작업 규칙(특히 담당 폴더, 콘텐츠 톤)
2. `docs/asset-spec.md` — 그림 규격(계약)
3. `src/game/assets.ts` — 키·크기·프레임 수·설명(무엇을 그릴지)·기준점
4. `src/game/textures/placeholders.ts`, `src/game/scenes/GalleryScene.ts` — 참고만(고치지 않아요)

## 고쳐도 되는 파일
- `assets-src/**` (새로 만들기)
- `scripts/build-assets.mjs` (지금은 빈 껍데기)
- `public/assets/**` (스크립트가 만드는 결과물)

그 밖의 파일은 고치지 않아요. 특히 `src/**`, `tests/**`, `package.json`, 계약 파일은 그대로 둬요. 바꿔야 할 것 같으면 최종 보고의 "필요한 변경"에 적어 주세요.

## 할 일
1. **팔레트** `assets-src/palette.json`: 32색 이내. 밝고 따뜻한 색 위주에 짙은 외곽선 색 1~2개, 피부색 3단계 이상을 넣어요. 글자 → 색 대응도 여기에 정의해요(투명은 `.`).
2. **원본 형식**: `assets-src/<kind>/<key>.txt`에 글자 하나 = 픽셀 하나인 격자로 그려요. 여러 프레임을 어떻게 적는지(가로로 붙이기, 빈 줄로 나누기 등)는 정해서 `assets-src/README.md`에 적어 둬요. 반복이 많은 그림(타일 변형, 프레임 차이)은 스크립트에서 변환해도 돼요(좌우 반전, 1px 이동 등).
3. **생성 스크립트** `scripts/build-assets.mjs`(Node 24, ESM). 쓸 수 있는 라이브러리는 이미 설치된 `pngjs`뿐이에요.
   - `public/assets/<kind>/<key>.png`를 만들어요. 여러 프레임은 가로로 이어 붙여요.
   - `public/assets/manifest.json`을 만들어요. 형식은 `docs/asset-spec.md`에 있어요(`version`, `palette`, `assets[{key, file}]`).
   - `assets-preview/contact-sheet.png`도 만들어요. 모든 그림을 `assets.ts` 순서대로 4배로 키워 한 장에 모은 검토용 그림이에요(라벨은 없어도 돼요).
   - 크기·프레임 수가 `assets.ts`와 다르거나 팔레트 밖 글자가 있으면 오류를 내고 멈춰요. Node 24는 `.ts` 파일의 타입을 지우고 바로 import할 수 있어서 `import { ASSETS } from '../src/game/assets.ts'`로 읽어도 돼요.
4. **그림 그리기**: `assets.ts`의 키를 전부 그려요(114개). 시간이 모자라면 이 순서로 우선해요: 타일·블록 → 캐릭터 → 소품 → 몹 → 아이콘 → 겹침 레이어 → 효과.

## 그림 스타일
- 3배로 확대해서 보는 게임이에요. 작은 크기에서도 무엇인지 알아보기 쉽게, 외곽선은 1px 짙은 색, 빛은 왼쪽 위에서 와요.
- 밝고 둥근 느낌. 몹과 보스도 무섭지 않고 장난꾸러기처럼 보이게 해요. 정화된 프레임(3)은 웃는 얼굴과 밝은 색이에요.
- **타일 마름모(32×16)**: 0~7행의 너비는 4, 8, …, 32px(가운데 정렬), 8~15행은 32, …, 4px예요(2:1 계단). 이렇게 그리면 이웃 타일과 이음새 없이 맞아요. 풀·흙·물 타일은 서로 붙어도 어색하지 않게 가장자리 색을 맞춰요.
- **블록(32×24)**: 위 16px은 타일과 같은 윗면 마름모, 아래 8px은 옆면이에요(왼쪽 옆면은 조금 밝게, 오른쪽은 어둡게).
- **캐릭터(16×24, 10프레임)**: 머리 약 8px, 큰 눈. 앞 프레임은 화면 오른쪽 아래, 뒤 프레임은 오른쪽 위를 봐요. 걷기 4프레임은 다리를 번갈아 움직이고 1px씩 위아래로 흔들려요.
  - `char-player`: 성별이 드러나지 않는 견습 탐험가(짧은 머리, 조끼, 가방).
  - `char-robi`: 작고 둥근 은색 로봇, 안테나, 화면 같은 얼굴.
  - `char-zen`: 공중에 떠 있는 따뜻한 분홍빛 등불 모양 AI.
  - NPC 3명(촌장 다온, 요리사 보리, 숲지기 솔)은 나이·옷차림이 다르게, 피부색도 다양하게 그려요.
- **겹침 레이어**: 모자·도구는 `char-player`의 같은 프레임 위에 얹었을 때 머리·손 위치가 정확히 맞아야 해요(걷기의 1px 흔들림 포함). 바퀴 모터는 `char-robi` 발밑에 맞춰요.
- **몹 4프레임**: 0~1 대기(살짝 움직임), 2 맞음(찡그림), 3 정화됨(웃음).
- **아이콘(16×16)**: 1px 여백. 카드 아이콘은 같은 종류끼리 같은 테두리 색으로 맞춰요(이동 = 파랑, 전투 = 빨강·파랑·초록, 반복 = 주황, 만약 = 보라).
- 기존 게임의 캐릭터·타일을 따라 그리지 않아요.

## 완료 기준
- `npm run assets`가 오류 없이 모든 PNG, `manifest.json`, `contact-sheet.png`를 만들어요.
- `npm test`가 통과해요. `tests/assets.test.ts`가 크기, 팔레트, 반투명 픽셀을 검사해요.
- `npm run build`가 통과해요.
- `npm run dev`를 켜고 `http://localhost:5173/?gallery`를 열면 모든 그림이 보이고, 아래쪽 5×5 풀밭에서 캐릭터·모자·지팡이·나무·상자가 칸 가운데에 맞게 서 있어요.

## 확인 명령
```bash
npm run assets && npm test && npm run build
```
