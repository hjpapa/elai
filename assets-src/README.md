# 엘라이 섬 그림 원본

계약 `src/game/assets.ts`의 186개 키, 총 515프레임을 그렸어요. PNG 생성은 설치된 Node 24와 `pngjs`만 사용해요.

## 텍스트 격자

- 1배 원본은 `<kind>/<key>.txt`, 2배 원본은 `hires/<kind>/<key>.txt`예요. 폴더가 밀도를 정하므로 파일 안에 헤더는 넣지 않아요. 글자 하나가 픽셀 하나예요.
- 각 프레임의 너비와 높이는 계약 크기에 밀도를 각각 곱해요(2배는 가로와 세로가 각각 2배예요). 공백·들여쓰기·주석은 넣지 않아요.
- 여러 프레임은 **빈 줄 하나**로 나눠요. 파일 마지막 줄바꿈 하나는 허용해요. UTF-8, LF/CRLF를 읽어요.
- `.`은 완전 투명이에요. 나머지 글자는 `palette.json`의 `colors`에서 색을 찾아요.
- PNG는 프레임을 왼쪽부터 가로로 이어 붙여요. 알파는 0 또는 255뿐이에요.

예를 들어 3×2, 2프레임이라면 이렇게 적어요(설명용이며 계약에 없는 키는 만들지 않아요).

```text
.Y.
YYY

.y.
yWy
```

## 색과 모양

공용 팔레트는 64색이에요. 처음 32색의 글자·순서·값은 보존하고 아래 C11 대응표의 새 32색을 뒤에 붙였어요. `O/D`는 짙은 외곽선, `S/A/a`는 돌·금속, `W/w`는 밝은 빛이에요. `H/h/K/k`는 피부색 4단계, `G/g/L/l`는 잎, `E/e/T/t`는 나무·흙, `R/r/P/p`는 붉은색·분홍색, `N/B/b/C/c`는 물·푸른빛, `V/v`는 보라, `Y/y`는 금빛이에요.

빛은 왼쪽 위에서 와요. 작은 물건은 1px 외곽선과 큰 면으로 구분해요. 지형은 붙였을 때 짙은 줄이 생기지 않게 가장자리를 바탕색으로 맞췄어요. 타일의 각 행 너비는 `4,8,12,16,20,24,28,32,32,28,24,20,16,12,8,4`이고 바깥은 투명이에요. 풀·꽃 타일의 테두리색은 같고, 물의 두 프레임도 테두리가 변하지 않아요.

1배 소품·캐릭터·몹은 `(너비/2, 높이-2)`에 발을 맞춰요. 옛 원본에는 단색 그림자가 남아 있어요. 2배 원본은 `(너비/2, 높이-4)`에 발을 맞추고 발밑 그림자를 그리지 않아요. 블록은 같은 32×16 윗면 아래에 8px 옆면을 붙이고 왼쪽을 밝게 해요.

캐릭터는 `앞 대기, 앞 걷기4, 뒤 대기, 뒤 걷기4` 순서예요. 걷기 1·3은 몸을 1px 올리고 다리와 손을 번갈아 움직여요. 장비도 같은 자세 계산을 써서 모자와 손잡이를 맞췄어요. 로비 바퀴의 접지는 고정이고 바퀴 무늬가 돌아가요. 젠은 다리 대신 등불과 술 장식이 떠서 흔들려요. 몹은 `대기, 살짝 움직임, 찡그림, 정화된 웃음` 순서예요. 효과는 반투명 대신 밝은 픽셀의 수와 간격으로 사라짐을 표현해요.

## 생성과 검토

```sh
npm run assets
npm test
npm run build
```

생성기는 모든 계약 키의 원본·크기·프레임 수·팔레트 글자를 먼저 검사해요. 오류가 있으면 기존 PNG를 쓰기 전에 멈춰요. 성공하면 `public/assets/<kind>/<key>.png`, `public/assets/manifest.json`, `assets-preview/contact-sheet.png`와 C11 비교판 `assets-preview/pilot-sheet.png`를 만들어요. 전체 검토판은 계약 순서이며 1배 그림은 4배, 2배 그림은 2배 최근접 확대로 표시 크기를 맞춰요. 검토판은 기존 `.gitignore`에 따라 커밋 대상에서 빠져요. 누락된 키를 임시 그림으로 조용히 넘기지 않아요.

`npm run dev` 후 `http://localhost:5173/?gallery`에서 게임 로딩과 발 기준점을 확인해요. 전체 검토용 그림은 갤러리 창의 높이와 관계없이 모든 프레임을 보여 줘요.

`tools/`에는 반복 그림을 편집하기 위한 선택적인 원본 작성 도구가 있어요. **평소 PNG 생성은 txt만 읽으며 도구를 실행하지 않아요.** txt를 직접 다듬은 뒤 작성 도구를 실행하면 그 수정이 덮어써지므로, 사용할 경우 도구 쪽에도 수정을 반영해 주세요.

```sh
node assets-src/tools/draw-terrain-effects.mjs
node assets-src/tools/draw-world-objects.mjs
node assets-src/tools/draw-characters.mjs
node assets-src/tools/draw-icons.mjs
```

Claude 검토 권장: 집 수리 전후, 덩굴문·입구 아치의 열림, 숲의 수호자 정화 표정, 앞/뒤 걷기의 모자·도구 정합, 줍기 손과 열쇠 배지 숫자의 3배 가독성이에요. 계약·갤러리·게임 코드에는 손대지 않았어요.

## C4 동굴 그림

`node assets-src/tools/draw-cave.mjs`는 동굴 그림 9종만 다시 그려요. 바닥·바위벽·수정·석순, 헬멧 램프를 쓴 하루, 메아리 박쥐와 대장, 메모리 칩 겹침·아이콘이에요. 로비 칩은 앞에서 몸통 왼쪽 가장자리, 뒤에서는 등판에 보이며 몸의 1px 움직임을 따라가요. 바퀴가 있는 19~22행과 겹치지 않아요. 대장은 별 장식으로 구분하고, 정화되면 민트색 웃는 얼굴로 바뀌어요.

## C5 사막 그림

`node assets-src/tools/draw-desert.mjs`는 사막 새 그림 8종을 만들어요. 기존 모래 타일을 그대로 쓰고 사암 벽, 선인장, 빨강/초록 신호등, 길잡이 나루, 신기루 도마뱀과 대장, 로비 센서를 더했어요. 신호는 빛뿐 아니라 멈춤 선/확인 표시로 구분해요. 센서는 로비 머리 옆에 붙어 등판 메모리 칩과 바퀴를 가리지 않아요.

## C7 연구소 그림

## C11 마을 고해상도 시범

시범 38키는 `hires/<kind>/<key>.txt`에서 읽어요. 같은 키의 옛 원본과 새 원본이 함께 있으면 새 원본을 쓰고 매니페스트에 `density: 2`를 적어요. 옛 원본은 26키 모두 그대로 보존해 비교와 복귀에 사용해요. 새 안내/UI 12키에는 옛 원본이 없어요. 새 원본이 잘못됐을 때는 옛 그림으로 몰래 대체하지 않고 오류로 멈춰요. 1배로 되돌릴 때는 해당 hires 파일을 다른 곳에 보관한 뒤 생성기를 실행해요(옛 원본이 있는 키에만 가능해요).

가로 띠의 PNG·아틀라스 프레임은 실제 2배 픽셀 크기예요. 한 장 아틀라스는 최대4096×4096이고 게임이 밀도로 나누어 기존 표시 크기로 그려요. 전체 원본·비교판·아틀라스를 먼저 검사한 뒤 결과를 기록해요.

`pilot-sheet.png`는 지시서의 38키 순서로 **왼쪽 옛 그림×4 / 오른쪽 새 그림×2**를 나란히 보여 줘요. 10프레임 캐릭터도 전 프레임을 비교해요. 새 키의 왼쪽에는 `NEW KEY - NO 1X SOURCE`라고 표시하며 빈 영역은 누락 오류가 아니에요.

선택적인 원본 작성/검증 도구:

